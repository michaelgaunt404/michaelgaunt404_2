Quick Overview

Hey hey —

Today’s 5-minute trick tackles a big gap I kept running into:

I needed to model something with both spatial structure and time dependencies, but nothing I found in R’s modeling universe would let me resample across both space and time without leakage.

What’s the modeling task?

Let’s say you want to spatially interpolate predictions (i.e., predict at new locations) and forecast in time (i.e., predict future values). Your model has to generalize both in space and in time.

If you don’t split your data smartly — say you train your model on one time slice and evaluate on the same locations a few days later — you might leak information across your train/test sets and falsely inflate your model’s performance.

Even worse, if you’re tuning a model and evaluating performance with leakage, you’re optimizing toward something that will crumble in production.

In order to do this, I wrote my own function that integrates with and extends the tidymodels’ existing sampling framework
And yes, I’m going to share it 😎

Goals:

  • Split the data spatially so no sensors (SOURCEIDs) appear in both train and test
  • Then temporally within each spatial fold using a sliding window

Leakage would allow the model to “peek” at test data by sharing sensors or future observations between train/test - which is bad!!!.

Step 1: Spatial Folds

We’ll take a slice of the data (two weeks in 2012 at one depth), and convert it to an sf object:

trainDat <- cookfarm %>%
  filter(altitude == -0.3,
         lubridate::year(Date) == 2012,
         lubridate::week(Date) %in% 13:14) %>%
  mutate(Date = as.Date(Date)) %>%
  st_as_sf(coords = c("Easting", "Northing"), crs = 26911)

Now we split spatially so each fold has unique sensors (SOURCEIDs).

You could also use spatial_clustering_cv() from the spatialsample package — that’s a great option too.

spatial_folds <- trainDat %>%
  group_vfold_cv(group = SOURCEID, v = 5)

Step 2: Rolling Origin… with Groups?!

Rolling origin resampling (sliding_window(), etc.) is great for time —
but it fails with grouped data, like multiple sensors.

It also expects a singular time signal so it just slices the row indices, ignoring your groupings.

So I wrote a helper that loops through each sensor group, applies rolling origin resampling, and merges the results:

create_grouped_rolling_origin():

create_grouped_rolling_origin <- function(data, initial, assess, cumulative = TRUE, skip = 0) {
  sensors <- unique(data$SOURCEID)
  splits_list <- list()
  i = 0
  
  for (sensor in sensors) {
    i = i + 1
    sensor_data <- data %>% 
      filter(SOURCEID == sensor) %>%
      arrange(Date)

    if (nrow(sensor_data) >= (initial + assess)) {
      ro <- rolling_origin(sensor_data, 
                           initial = initial, 
                           assess = assess, 
                           cumulative = cumulative, 
                           skip = skip) %>% 
        mutate(sensor = sensor)

      splits_list[[i]] = ro
    }
  }
    
  splits_list = splits_list %>% 
    reduce(bind_rows) %>%  
    group_by(id_1 = id) %>% 
    group_map(~{
      temp_analysis = .x$splits %>% 
        map_df(~ analysis(.x))
      
      temp_assessment = .x$splits %>% 
        map_df(~ assessment(.x))
      
      combined_data <- bind_rows(temp_analysis, temp_assessment)
      n_analysis <- nrow(temp_analysis)
      
      structure(
        list(
          data = combined_data,
          in_id = 1:n_analysis,
          out_id = (n_analysis + 1):nrow(combined_data)
        ),
        class = c("sliding_period_split", "rsplit")
      )
    })
  
  inner_rset <- rsample::new_rset(
    splits = splits_list,
    ids = paste0("Resample", seq_along(splits_list))
  )
  
  class(inner_rset) <- c("sliding_period", "rset", "tbl_df", "tbl", "data.frame")
  
  return(inner_rset)
}

Apply it to one spatial fold:

example_fold = spatial_folds$splits[[1]] %>% analysis()

inner_resamples = create_grouped_rolling_origin(
  data = example_fold,
  initial = 8,
  assess = 2,
  cumulative = TRUE)

Helper function:

view_split_groups_date <- function(all, train, val){
  bind_rows(
    all %>%
      count(Date) %>%
      mutate(SOURCEID = "All Data", type = "all"),
    train %>%
      count(SOURCEID, Date) %>%
      mutate(type = "Train"),
    val %>%
      count(SOURCEID, Date) %>%
      mutate(type = "Validation")
  )
}

Why Bother?

This might feel like a lot, but it’s one of those cases where doing it right matters:

  • Most tools only resample in time or space — not both (and def not when there’s repeated measures)
  • This custom approach avoids data leakage in both dimensions
  • Great for spatiotemporal interpolation and forecasting

And: if you’re tuning a model with tune_grid() or workflow_map(), nesting this inside your outer spatial folds helps ensure leakage doesn’t sneak in during hyperparameter selection — especially with temporal dependencies in the data.
